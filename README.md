# TSAnnotate - Fast Traffic Sign Annotation

This tool supports the creation of traffic sign detection and recognition datasets by leveraging pre-trained 
models to annotate traffic scenes from videos or images. It processes videos and images and exports the 
pre-labeled scenes to [Label Studio](https://labelstud.io/) for manual verification and correction.

## Installation

1. If not already available on your system, install FFmpeg
2. Python 3.10 or newer is required
3. Install from PyPI using `pip install TSAnnotate`
4. Install Label Studio using `pip install label-studio`

## Workflow

The workflow for creating traffic sign detection and recognition datasets using TSAnnotate and Label Studio
is the following:
1. Collect: obtain traffic scene data as videos or images
2. Label: pre-label traffic scenes with TSAnnotate; videos are sampled at the given rate and images are
processed as they are
3. Verify: manually check and correct the labels using Label Studio
4. Export: TSAnnotate creates train/test splits, filters out background images and converts annotations into
the YOLO format

## How to use

This section contains detailed information on each step.

### Data Collection

TSAnnotate can read either individual files or entire directories. In case of directories, all subdirectories will
be recursively searched for image and video files. The following file formats are supported:
- Videos: mov, mp4
- Images: jpg, jpeg, png

Unsupported files will be ignored, if the given input is a directory, or cause an exception, if the file is the 
only input.

### Label

Run the following command to start pre-labeling:

`ts-annotate label /path/to/input`

Replace `/path/to/input` with the path to your input file or directory. The labeled images are exported to 
an `output` directory in the current working directory. See the Arguments section on how to change this, and
other default behaviors. Annotations are stored in the Label Studio specific [format](https://labelstud.io/guide/task_format).

### Verify

Verification and correction is done manually in Label Studio. To enable import of local files to Label Studio,
run

```
export LABEL_STUDIO_LOCAL_FILES_SERVING_ENABLED=true
export LABEL_STUDIO_LOCAL_FILES_DOCUMENT_ROOT="/path/to/output"
```

If you are using Windows the commands are different, please ask an LLM of your choice how to do this. 
Replace `/path/to/output` with the output directory of the previous step. This must be done every time 
Label Studio is started. Then run Label Studio:

`label-studio start`

Label Studio should automatically open in your browser, otherwise visit `http://localhost:8080` and follow these steps: 
1. Create an account and sign in
2. Create a new project
3. Enter a name for the project
4. Go to the "Labeling setup" tab at the top of the window.
5. Select "object detection with bounding boxes"
6. On the left side, under "Labeling Interface", switch to the "Code" tab
7. Replace the entire content of the text box with the content of "labeling_interface.html" generated by 
TSAnnotate in the output directory
8. Press "Save" in the top right. **Do not import any data yet.**
9. Press "Connect cloud storage"
10. Select "Local files" and press "Next"
11. Chose a "Storage Title" for this connection, e.g., "Images" as this is the image import
12. Point "Absolute local path" to the "images" directory inside the output generated by TSAnnotate,
e.g., `/path/to/output/images`
13. Optional: press "Test connection" to make sure the path was entered correctly
14. Press "Next"
15. Don't change anything on this page and press "Next"
16. Press "Save". **Do not press "Save & Sync".**
17. The same process is now repeated to import the annotations. Press "Add Source Storage"
18. Select "Local files" and press "Next"
19. Chose a "Storage Title", e.g., "Annotations"
20. Point "Absolute local path" to the "annotations" directory inside the output, e.g., `/path/to/output/annotations`
21. Optional: test the connection
22. Press "Next"
23. Don't change anything on this page and press "Next"
24. Press "Save & Sync", depending on the amount of images this may take a while

You can now click the name of you project on the top of the page to get to a list of the images. From here you can
select images. Some notes on using Label Studio:
- Remove duplicate/similar images directly from the list by marking them using the checkbox in the first column
and selecting "Delete Tasks" from the drop-down menu above
- Labels are based on the [ETSD](https://ieeexplore.ieee.org/abstract/document/8558481), some of them are "special"
versions of regular signs: "Cyclists-Pedestrians (s)", "Cycle track (s)", "Cyclists entering or crossing (s)", 
"Uneven road (1 bump)", "Pass right (s)"; you will probably never need them, use the regular ones instead
- Most YOLO implementations scale images down before processing, so detection of small signs is difficult; depending
on the intended use-case of your dataset, annotating very small traffic signs might not be necessary
- Save changes made to the annotations by pressing "Update" in the bottom right

When done with labeling:
1. Go to the project page (the list of all images) and press "Export" in the top right.
2. Select "JSON" (should be the default) and press "Export" in the bottom left; the file should be saved to the
"downloads" directory and be named something like "project-1-at-2026...json"

### Export

After the verifying and correcting annotations, TSAnnotate will create train and test split, filter out background
images and export the data in the YOLO format for easy training. Run the following command:

`ts-annotate export /path/to/annotations.json`

Where `annotations.json` is the file exported by Label Studio. 

This step requires access to the outputs generated by the "label" step. By default, they will be saved to an
`output` directory in the current working directory. TSAnnotate will attempt to automatically detect them. If that
fails, pass the path to the output using the `data_path` argument by using the same path used as `output_path` in
the "label" step.

The results will be saved into `output/new_dataset`. The location can be changed by using the `output_path` 
and `name` arguments.

## Arguments

This section describes the argument that can be passed to TSAnnotate. Some of them have different meanings depending
on the task that is run.

### Positional Arguments

TSAnnotate expects two positional arguments:

`ts-annotate [task] [input_path]`

- task: defines the task that will be run and can be either "label" or "export"
- input path: path to the input data, depending on task this is either a directory or single video/image file 
("label" task) or a JSON file ("export" task)

### Optional Arguments

The following optional arguments can be passed. Some of them are only supported in one task.
Run `ts-annotate --help` for details.

| Argument | Label | Export | Default |
| -------- | ----- | ------ | ------- |
|-o/--output_path | Path to save labeled images to | Path to save dataset to | output |
|-sr/--sample_rate | Rate at which images are sampled from videos | - | 1 |
|-d/--data_path | - | Path to output of "label" task | - |
|-ts/--test_split | - | Share of images in test split | 0.1 |
|-vs/--val_split | - | Share of images in validation split | 0.1 |
|-br/--background_ratio | - | Maximum share of background images | 0.1 |
|-n/--name | - | Name of dataset directory | new_dataset |
|-l/--labels | File with labels used for annotation | File with labels used for annotation | - |
|-m/--model | Model to use for labeling | - | - |
|-fs/--filter_similar | Remove similar consecutive images |- | - |
|-si/--sort_inputs | Sort inputs by numbers extracted from file names | - | - |

## Customization

This section contains more detailed explanations about the usage of some of the arguments that customize
the tools functions.

### Labels

The default labels used to annotate images are based on the [ETSD](https://ieeexplore.ieee.org/abstract/document/8558481) paper, expanded with some classes to
represent signs that were not in the original dataset. A table listing all labels can be found 
[here](https://huggingface.co/datasets/dsilbermann/european_traffic_signs). 
Custom labels can be used by passing a CSV file to the `labels` argument. The file should contain lines 
of the following format: 

`label,short label,color`

Where:

- *label* is the full name of the label
- *short label* is a more compact name for the label used to save space in the Label Studio UI; if the label
names are already short, it may be the same as the full label
- *color* is a hex color code used to highlight groups of labels in the Label Studio UI

While all of these values must be present, nothing prevents you from using the same text as *label* and 
*short label*, or the same *color* for all labels. Do not include a header line in the file.

### Model

By default, pre-labeling is done using a YOLO26 model trained on a collection of European traffic sign
detection datasets, which is pulled from 
[HuggingFace](https://huggingface.co/dsilbermann/traffic_sign_detection_europe). You can use a custom
model by passing it to the `model` argument. Currently, only models based on 
[Ultralytics](https://www.ultralytics.com/) [YOLO](https://docs.ultralytics.com/models/yolo26)
are supported. Models can either be stored locally or on HuggingFace. In that case, repo ID and filename
must be passed like this: `user/repo/filename.pt`
